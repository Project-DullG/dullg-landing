# 스피킹 공부 연결 계획

작성일: 2026-09-08

> 이 문서는 2026-09-08의 초기 연결 계획이다. 이후 사용자가 실제 연결·계정별 진도 저장·음성 확대를 승인했다. 현재 구현과 배포 상태는 [운영 기록](speaking-implementation.md)을 따른다.

## 1. 현재 작업 범위

사용자가 영어 공부 프로젝트를 완성한 뒤 사이트에 연결한다. 지금은 연결 계획만 작성한다.

- 실제 메뉴·페이지·로그인 기능은 추가하지 않는다.
- 원본 영어 공부 프로젝트를 수정하거나 복사하지 않는다.
- 배포, 인증코드 등록, 데이터베이스 변경은 하지 않는다.
- 미완성 코스를 줄이거나 새 문항으로 채우지 않는다. 연결 시점의 완성본을 다시 확인한다.

## 2. 사용자가 정한 내용

- 사이트에 **스피킹 공부** 항목을 만든다.
- **구글 로그인 → 전달받은 공통 인증코드 확인 → 학습 페이지** 순서로 접속한다.
- 구글 로그인만으로 학습 자료를 열 수는 없다.
- 사용자가 지정한 초기 인증코드는 배포 시 서버 전용 환경변수로 등록한다. 이 문서나 소스 코드에 적지 않는다.
- 앞으로 학습 페이지를 추가할 수 있게 구성한다.

별도로 요청하지 않은 학습 기록 저장, 녹음, 자동 채점, 유료 API 연결은 이번 연결 범위에 넣지 않는다.

## 3. 메뉴와 페이지 배치 제안

**스피킹 공부는 수강생 자료실과 별도 항목으로 둔다.** 수강생 자료실은 기존 수업 자료를 찾는 곳으로 유지한다.

| 위치 | 역할 | 공개 범위 |
| --- | --- | --- |
| 주요 메뉴의 `스피킹 공부` | 로그인 안내 페이지로 이동 | 메뉴 이름만 공개 |
| `/speaking` | 구글 로그인과 인증코드 입력 | 공개 접속 가능, 학습 내용 없음 |
| `/speaking/study` | 완성된 영어 공부 프로젝트의 학습 화면 | 구글 로그인과 코드 확인 후 접속 |
| `/speaking/[추가 과정]` | 추후 실제로 제공하는 학습 페이지 | 같은 인증 절차 적용 |

교육 메뉴와 수강생 자료실 사이에 스피킹 공부를 배치하는 안을 우선 검토한다. 메뉴가 좁아지는 화면에서는 기존 모바일 메뉴를 사용하고, 글자를 줄이거나 두 줄로 밀어 넣지 않는다.

첫 연결 때 과정이 하나뿐이면 인증 후 바로 학습 화면을 연다. 빈 과정 목록이나 ‘준비 중’ 카드를 만들지 않는다. 실제 과정이 둘 이상 준비되면 `/speaking`을 과정 선택 화면으로도 사용한다.

## 4. 인증 설계

기존 사이트의 Firebase 구글 로그인과 서버 세션 검증을 재사용한다. 학원 관리 페이지의 원장·학생 권한과 스피킹 접근 권한은 분리한다. 스피킹 이용자에게 학원 관리 권한을 부여하지 않는다.

1. 구글 로그인을 완료하면 서버에서 토큰의 서명, 유효기간, 로그인 제공자를 확인한다.
2. 로그인된 사용자에게만 인증코드 입력 화면을 보여준다.
3. 서버에서 전달받은 코드를 환경변수의 값과 비교한다.
4. 코드가 맞으면 해당 구글 계정과 로그인 세션에 묶인 접근 쿠키를 발급한다.
5. 학습 화면과 학습 자료를 제공하는 모든 서버 경로에서 두 인증 조건을 다시 검사한다.

보호 기준:

- `SPEAKING_ACCESS_CODE`는 서버 전용 값으로 관리한다. `NEXT_PUBLIC_` 변수, HTML, 브라우저 JavaScript, URL, 로그에 넣지 않는다.
- 접근 쿠키에는 인증코드를 저장하지 않는다. 별도 서버 비밀키로 서명하고 `HttpOnly`, `Secure`, `SameSite`를 적용한다.
- 코드 또는 서버 비밀키를 바꾸면 기존 접근 쿠키가 더 이상 통과하지 않도록 한다.
- 인증 설정이나 인증 서비스가 잘못되면 자료를 공개하지 않고 오류 안내를 보여준다. 체험용 우회 로그인은 만들지 않는다.
- 페이지 상위 레이아웃 검사만 믿지 않는다. 하위 페이지, 서버 액션, 자료 제공 경로에서도 검사한다.
- 학습 문항과 답변 예시는 인증 후 서버에서 전달한다. 클라이언트 공통 번들에 전체 자료를 넣지 않는다.
- 보호할 이미지·PDF는 `public/`에 두지 않는다. 인증을 검사하는 경로나 비공개 저장소에서 제공한다.
- 학습 응답에는 개인용·저장 금지 캐시 정책을 적용한다. 검색 차단은 보조 수단이며 인증을 대신하지 않는다.
- 인증코드 입력 횟수를 서버 저장소에서 제한한다. 브라우저 쿠키를 지워도 실패 횟수가 초기화되지 않게 한다.

운영값 제안: 접근 유효기간 12시간, 계정별 인증코드 입력 1시간당 5회. 연결 전에 실제 이용 방식에 맞춰 확정한다. 짧은 공통 코드는 전달·추측될 수 있으므로 고도의 기밀 자료나 민감한 개인 기록을 보호하는 수단으로 사용하지 않는다. 특정 구성원만 허용해야 한다면 계정별 승인이나 초대 방식이 추가로 필요하다.

## 5. 원본 프로젝트 연결 방식

검토한 원본: 사용자가 제공한 `영어 공부/web-package`.

원본은 React 학습 화면이며, 현재 사이트에도 React·Next.js가 있으므로 사이트 안의 학습 페이지로 옮길 수 있다. 별도 사이트를 iframe으로 넣는 방식은 우선 사용하지 않는다. 외부 원본 주소가 공개돼 있으면 본 사이트의 로그인만으로 접근을 제한할 수 없기 때문이다.

연결 시에는 다음 항목만 선별해 가져온다.

- 완성된 학습 화면과 필요한 조작 기능
- 문항·학습 일정·발음 자료
- 출처와 사용 조건을 확인한 학습 이미지

원본의 루트 레이아웃, 전역 CSS, 배포 설정, 전체 패키지 목록은 덮어쓰지 않는다. 기존 사이트의 버튼·글꼴·여백 규칙을 사용하고, 학습 화면 스타일은 해당 화면 안에만 적용한다.

예상 코드 구분:

```text
app/speaking/                 로그인 안내와 보호된 학습 경로
components/speaking/          인증 입력과 학습 화면
lib/speaking/access/          서버 인증·접근 권한 검사
lib/speaking/catalog/         서버에서 제공하는 과정·문항 자료
private-assets/speaking/     인증 후 제공할 학습 이미지·문서
tests/                       접근 차단·문항 연결 검사
```

위 경로는 설계안이며 아직 생성하지 않는다. 실제 완성본의 파일 구조를 확인한 뒤 최소한의 변경으로 연결한다.

## 6. 현재 원본에서 발견한 확인 사항

이 항목은 2026-09-08에 읽은 파일 기준이다. 원본이 작업 중이므로 연결 전에 다시 확인한다.

| 항목 | 현재 상태 | 연결 전 확인 |
| --- | --- | --- |
| 30일 코스 | 코스가 참조하는 문항 중 20개가 현재 문항 목록에 없음 | 모든 학습일의 문항이 실제로 존재하는지 검사 |
| 누락 문항 처리 | 없는 문항을 선택하면 첫 문항으로 대체됨 | 다른 문제를 조용히 표시하지 않도록 수정 |
| 학습 이미지 | 이미지 2장이 있으며 상대경로 사용 | 보호된 자료 경로와 연결하고 표시 확인 |
| 연구 보고서 | 화면의 PDF 링크에 대응하는 파일이 패키지에 없음 | 완성본 파일·공개 범위 확인 또는 링크 제외 |
| 스타일 | 일부 화면 클래스의 스타일이 없고 전역 선택자가 있음 | 필요한 스타일을 보완하고 기존 사이트와 분리 |
| 학습자 설명 | 요청문에 특정 학습자의 수준·학교 목표가 포함됨 | 여러 사람이 사용할 화면에서는 개인 조건 제거 |
| 저장 | 코스·학습일·시간만 같은 기기의 브라우저에 저장 | 계정별 저장 키 분리, 서버 동기화로 오인하지 않게 안내 |
| 듣기 | 브라우저 합성 음성 사용 | 지원 여부와 온라인 음성의 외부 전송 가능성 안내 |
| 녹음·채점 | 현재 구현되지 않음 | 해당 기능이 있는 것처럼 설명하지 않음 |
| GPT 연결 | 요청문 복사와 외부 대화 링크 | 자동 답변·채점 기능으로 소개하지 않음 |

개인 프로필, 복습 대기열, 실제 수업 기록, 녹음, 비공개 연구 문서는 사이트로 옮기지 않는다. 나중에 개인 학습 기록 저장이 필요하면 계정별 접근 권한과 보관·삭제 방법을 별도로 설계한다.

## 7. 완성 후 진행 순서

1. 사용자가 연결할 완성본과 이용 범위를 지정한다.
2. 원본 변경사항, 자료 사용 조건, 개인 정보 포함 여부를 다시 확인한다.
3. 과정·문항 ID와 이미지·문서 경로의 무결성을 검사한다.
4. 구글 로그인과 인증코드 확인을 연결한다.
5. 학습 화면을 옮기고 메뉴를 추가한다.
6. 보호 경로 직접 접속, 잘못된 코드, 입력 제한, 계정 변경, 로그아웃, 쿠키 만료·변조를 검사한다.
7. 휴대전화 화면, 키보드 조작, 음성 미지원 상태, 모든 학습일의 문항 이동을 확인한다.
8. 구글 로그인 허용 도메인과 서버 전용 환경변수를 확인한다.
9. 사용자의 연결·배포 요청 범위에 따라 검증된 결과를 게시한다.

실제 구글 계정 로그인은 자동 검사로 완료했다고 추정하지 않는다. 게시 전 정상 계정의 전체 접속 절차를 별도로 확인한다.

참고 문서: [Firebase 구글 로그인](https://firebase.google.com/docs/auth/web/google-signin), [Firebase 서버 세션 쿠키](https://firebase.google.com/docs/auth/admin/manage-cookies).

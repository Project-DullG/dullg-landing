# Project DullG 통합 웹사이트·웹앱 초안 v0.1

- 작성일: 2026-07-23
- 목적: 지금까지의 사업 기록, 영어학원 MVP 산출물, 머더미스터리 콘텐츠·검증 자산을 바탕으로 웹사이트와 웹앱의 역할·범위·확장 순서를 한 문서에 정리한다.
- 상태: 내부 설계 초안. 확정된 기능 명세, 개발 일정, 개인정보 처리방침 또는 교육 효과 검증 결과가 아니다.

## 1. 이 문서가 전제하는 현재 사실

### 1.1 현재 영어교육 MVP

- 첫 구매 고객은 중소형 영어학원·공부방의 원장과 강사다.
- 첫 제품은 초등학교 6학년 수준을 기준으로 한 4차시 영어 미스터리 프로젝트 실물 키트다.
- 수업은 영어 단서를 읽고, 질문·추측·반박하며, 사건 보고서를 만드는 흐름이다.
- 현 MVP는 카드·보드·개별 스토리책자·워크북·규칙서·교사용 진행안과 수동 리포트를 우선 검증한다.
- 초기 범위에서는 학원생 관리, 주간·월간 추이, 학생·학부모용 앱, 음성 원본 수집, 자동 성취 판정을 제외했다.

### 1.2 이미 쌓인 확장 기반

- 평가 초안에는 핵심 단서 선별, 맥락 이해, 동기 추론, 인과 추론, 근거 기반 판단, 설명·보고 표현과 상호작용 관찰 요인이 있다.
- 기존 테스트베드에는 카드 공개 시점, 영어 카드 여부, 최종 판단, 선택 근거, 역할, 회차별 반응을 연결해 볼 필요가 확인됐다.
- 머더미스터리 자산에는 역할지, 단서 카드, 라운드, 최종 답안, 진행자 자료를 분리하고 검증하는 제작 구조가 있다.
- `my`의 변환·검증기는 교육용 수업자료까지 생성·검수할 수 있는 기술 자산이지만, DullG 내부 `murder_wizard_v2`와의 승계·병합 관계는 아직 결정되지 않았다.

### 1.3 이 초안의 해석

Project DullG는 단순 보드게임 판매가 아니라, **학생이 이야기 속 증거를 읽고 판단을 설명하는 경험을 수업·게임·리포트로 누적시키는 콘텐츠 플랫폼**으로 확장할 수 있다. 다만 이 확장은 실물 MVP의 유료 파일럿과 운영 검증 뒤에 단계적으로 진행한다.

## 2. 제품 구조: 공개 사이트와 웹앱을 분리한다

```text
브랜드 사이트
  ├─ 영어학원·교사용 랜딩페이지
  ├─ 머더미스터리 콘텐츠 허브
  └─ 자료 요청·파일럿 문의

웹앱
  ├─ 학원 관리자 공간
  ├─ 교사 수업 운영 공간
  ├─ 학생 게임·기록 공간
  └─ 학부모 공유용 결과 요약

제작·운영 도구 (별도 권한)
  ├─ 콘텐츠·에피소드 관리
  ├─ 카드·문항·루브릭 관리
  └─ 리포트 템플릿·파일럿 데이터 검토
```

### 2.1 공개 사이트의 역할

공개 사이트는 기능을 모두 제공하는 곳이 아니라 고객이 제품을 이해하고 다음 행동을 선택하게 하는 입구다.

| 경로 | 첫 방문자 | 첫 행동 | 전달해야 할 가치 |
|---|---|---|---|
| `/academy` | 원장·강사 | 검토 자료 요청 또는 파일럿 문의 | 준비 부담이 낮고, 수업 결과물을 남길 수 있는 영어 프로젝트 수업 |
| `/mystery/play` | 플레이어·구매자 | 작품·체험 탐색 | 역할·단서·선택으로 완성되는 몰입형 추리 경험 |
| `/mystery/create` | 창작자·기관 | 도구 상담 또는 대기 신청 | 원작 근거와 플레이 구조를 분리·검증하는 제작 지원 가능성 |
| `/` | 브랜드를 처음 접한 사람 | 목적별 경로 선택 | 스토리, 증거, 토론, 판단을 경험으로 설계하는 브랜드 |

광고·소개·커뮤니티에서 유입된 영어학원 고객은 반드시 `/academy`로 직접 들어온다. 메인에서 영어교육과 머더 콘텐츠 중 무엇인지 다시 고르게 하지 않는다.

### 2.2 웹앱의 역할

웹앱은 아래의 세 가지를 하나의 데이터 흐름으로 연결한다.

1. 교사가 수업을 준비하고 게임 세션을 연다.
2. 학생이 게임 안에서 단서·판단·최종 보고를 남긴다.
3. 교사·학원·학부모가 과장 없는 활동 결과 리포트를 확인한다.

## 3. 사용자와 권한

| 역할 | 핵심 목적 | 초기 권한 |
|---|---|---|
| 브랜드 운영자 | 콘텐츠 품질, 기관·교사 관리, 리포트 기준 관리 | 기관 생성, 콘텐츠 배포, 운영 데이터 열람, 템플릿 관리 |
| 학원 관리자/원장 | 반 운영 현황과 도입 결과 확인 | 교사·반 관리, 수업 요약·재주문·기관 리포트 열람 |
| 교사 | 한 차시를 안정적으로 진행하고 결과를 남김 | 세션 생성, 학생 초대, 카드/라운드 진행, 관찰 태그, 리포트 검수 |
| 학생 | 게임 참여와 자기 결과 확인 | 초대 코드 입장, 역할·단서 열람, 답안·자기평가 제출, 개인 기록 열람 |
| 학부모 | 자녀의 수업 결과를 이해 | 교사가 공유한 읽기 전용 결과 요약 열람 |
| 머더 콘텐츠 창작자/기관 | 작품 제작·검증 요청 또는 도구 사용 | 별도 계약·권한이 확정된 뒤 별도 작업공간 제공 |

학생 계정은 초기부터 장기 회원가입을 강제하지 않는다. 수업 초대 코드와 가명 또는 기관 내부 ID로 시작하고, 개인 장기 추이를 제공하기로 결정된 뒤에만 계정 연결·보호자 동의·보존 정책을 설계한다.

## 4. 영어학원용 웹앱의 핵심 사용자 흐름

### 4.1 교사 흐름

```text
로그인
→ 반 선택 또는 새 반 생성
→ 에피소드·난이도·수업 차시 선택
→ 수업방 생성 및 학생 초대코드 발급
→ 라운드·카드 공개 진행
→ 관찰 태그와 최종 보고 회수
→ 리포트 초안 검수
→ 원장·학부모 공유 여부 선택
```

### 4.2 학생 흐름

```text
초대코드 입력
→ 가명/기관 ID 확인
→ 역할·공개 정보·과제 확인
→ 팀 또는 개인의 단서 판단 기록
→ 최종 판단 + 근거 + 짧은 보고문 제출
→ 자기평가(재미·난이도·다음 참여 의향)
→ 허용된 범위에서 개인 활동 기록 확인
```

### 4.3 학원 관리자 흐름

```text
기관 대시보드
→ 이번 달 수업 수·활성 반·교사 운영 현황
→ 수업별 완료율·교사 준비시간·리포트 발행 현황
→ 학생 개인을 식별하지 않은 반/기관 요약
→ 다음 에피소드·이용권·파일럿 피드백 확인
```

## 5. 콘텐츠와 게임을 공통 데이터로 다룬다

영어 수업용 미스터리와 머더미스터리 작품은 판매 대상과 톤이 다르다. 그러나 세션 운영에 필요한 공통 단위는 공유할 수 있다.

| 공통 단위 | 예시 | 웹앱에서 쓰는 이유 |
|---|---|---|
| 콘텐츠 | 영어 미스터리 1회차, 5인 머더 작품, 10분 미니게임 | 무엇을 운영했는지 구분 |
| 세션 | 특정 반의 2026-08-10 2차시 | 실제 수업·플레이 기록의 단위 |
| 역할/팀 | 학생 역할, 팀 이름, 게임 내 목표 | 정보와 행동을 배분 |
| 콘텐츠 요소 | 카드, 단서, 질문, 퀴즈, 라운드, 봉인 자료 | 공개 시점·해금·응답 연결 |
| 이벤트 로그 | 카드 공개, 힌트 사용, 답 변경, 보고 제출 | 수업·게임 흐름을 복원 |
| 관찰 태그 | 영어 카드 해석, 단서 연결, 메타 추리, 발언 참여 | 전체 음성 수집 없이 필요한 장면만 기록 |
| 결과물 | 최종 지목, 근거 2개, 영어 문장, 팀 보고서 | 리포트와 다음 수업의 근거 |

현재 테스트베드가 보여 준 핵심은 단순 정답률보다 카드별 이해·연결·반영 여부와 근거 회수율이다. 따라서 앱은 처음부터 "맞힌 사람 순위"만 저장하지 않고, 카드·근거·보고의 연결을 남겨야 한다.

## 6. 리포트 설계 원칙

### 6.1 학생 개인 리포트

- 이번 수업에서 수행한 활동: 읽은 단서, 참여한 역할, 제출한 판단과 보고문
- 핵심 단서 선별, 맥락·동기·인과 이해, 근거 기반 판단, 설명·보고 표현의 활동 기록
- 교사가 확인한 참여·협력 관찰 태그
- 다음 활동 제안: 보충이 필요한 카드 유형, 다음 에피소드 난이도, 다시 써 볼 문장 틀

### 6.2 교사·원장 리포트

- 수업 운영: 소요 시간, 힌트·개입 횟수, 완료율, 교사 준비시간
- 콘텐츠 반응: 영어 카드 이해 확인, 핵심 카드 회수, 최종 보고 완성, 난이도·재미 응답
- 반 단위: 근거를 두 개 이상 든 비율, 보고서 완성 비율, 토론 관찰 분포
- 다음 버전 판단: 카드 난이도, 공개 순서, 교사용 진행안 수정 필요

### 6.3 표현의 경계

리포트는 공인 심리·문해력 진단이나 성적 향상 증명서가 아니다. 학생이 수업 중 단서를 읽고 판단을 설명한 활동 기록이며, 평가도구의 신뢰도·타당도는 별도 표본과 절차로 검증해야 한다.

## 7. 랭킹·배지 설계 원칙

랭킹은 재방문과 게임 몰입에 도움을 줄 수 있으나, 교육 서비스의 첫 기준으로 두지 않는다.

| 단계 | 가능한 요소 | 제한 |
|---|---|---|
| 초기 파일럿 | 세션 완료, 보고서 제출, 팀 미션 달성 배지 | 기관 밖 비교·공개 순위 없음 |
| 웹앱 v1 | 개인 성장 카드, 반별 협력 미션, 교사 공개형 리그 | 단일 점수로 능력을 서열화하지 않음 |
| 웹앱 v2 이후 | 시즌형 추리 리그, 작품별 도전 기록, 익명·동의 기반 이벤트 | 연령, 공개 범위, 점수 산식, 부정행위·낙인 위험을 별도 검토 |

권장되는 보상 축은 `추리`, `근거`, `협력`, `표현`, `탐색`처럼 여러 행동을 분리해 보여 주는 방식이다. 학생의 학업 능력 또는 성격을 단일 점수로 규정하지 않는다.

## 8. 단계별 범위

### 단계 0 — 공개 랜딩과 수동 파일럿

- 영어학원 랜딩페이지, 검토 자료 요청, 파일럿 문의 폼
- 실물 키트 1개 에피소드와 수동 리포트
- 교사·원장 인터뷰 및 실제 운영 로그 수집
- 목적: 앱 없이도 유료 파일럿 의향과 운영 문제를 확인

### 단계 1 — 파일럿 운영 웹앱

- 기관·교사 로그인
- 반/세션 생성, 학생 초대 코드, 가명 기반 참여
- 한 개의 짧은 디지털 활동 또는 게임 보조 화면
- 최종 판단·근거·보고문 제출
- 교사 관찰 태그와 수동 검수형 리포트
- 목적: 종이·폼으로 흩어진 파일럿 기록을 한 세션 데이터로 연결

### 단계 2 — 학원용 운영 대시보드

- 콘텐츠 라이브러리와 차시별 운영 템플릿
- 학생의 허용 범위 내 개인 활동 추이
- 원장용 반·기관 요약과 재주문 흐름
- 학부모 공유용 읽기 전용 결과 페이지
- 반 단위 배지·협력 미션

### 단계 3 — 플랫폼 확장

- 여러 난이도의 영어 프로젝트·미니게임·스토리 콘텐츠
- AI 리포트 초안 지원(교사 최종 검수 전제)
- 머더미스터리 플레이/작품 허브와 계정·세션 체계의 선택적 연결
- 창작자·기관용 콘텐츠 제작·검증 작업공간

단계 2와 3은 파일럿에서 교사 준비시간, 리포트 사용 의향, 재구매 의향, 학생의 반복 사용 의향이 확인된 뒤에만 착수한다.

## 9. 초기 데이터 항목과 개인정보 원칙

### 9.1 초기 저장 항목

| 범주 | 최소 항목 |
|---|---|
| 기관·교사 | 기관명, 담당자, 수업 조건, 연락·동의 상태 |
| 학생 | 가명 또는 기관 내부 ID, 학년/수준 범주, 반 연결 |
| 세션 | 콘텐츠·차시·시간·인원·진행 교사 |
| 활동 | 공개 카드, 힌트, 제출 답, 근거, 보고문, 난이도·재미 응답 |
| 교사 관찰 | 필요한 태그, 수업 시간, 준비시간, 운영 이슈 |

### 9.2 초기에는 저장하지 않는 항목

- 학생의 전체 음성 원본과 상시 녹화 영상
- 필요 없는 실명, 상세 성적, 성격·심리 진단 정보
- 자동 성취 판정 결과를 사람 검수 없이 학부모에게 보내는 기능

개인 장기 추이, 학부모 접근, 외부 랭킹은 학생 식별·보호자 동의·열람·정정·보존·삭제 기준을 먼저 확정한 뒤에 도입한다.

- 원장·교사의 리포트 사용 의향과 재주문 의향

- 학생의 재미·난이도·다음 참여 의향

이 지표는 제품·운영 개선을 위한 것이며, 초기부터 "문해력 향상"이나 "성적 상승"을 증명하는 지표로 사용하지 않는다.

# 사용자 유형별 검토와 수정

2026-09-13. 아래 사용자 유형은 설계를 검토하기 위해 정한 가정이다. 실제 사용자 인터뷰나 브라우저 플레이 결과가 아니다.

| 사용자 유형 | 하려는 일 | 검토 기준 |
| --- | --- | --- |
| 추리 게임을 처음 하는 사람 | 무엇을 눌러야 하는지 알고 실종자를 찾는다 | 읽기와 자료 선택을 구분할 수 있는가. 다음 행동이 앞서 확인한 사실과 맞는가. |
| 대사와 단서를 꼼꼼히 읽는 사람 | 증언을 다시 보고 자료를 비교한다 | 자료를 바로 열 수 있는가. 원하는 문서를 찾고 들었던 질문을 구분할 수 있는가. |
| 잠깐씩 하다가 돌아오는 사람 | 중단한 곳을 확인하고 이어 한다 | 읽던 도입과 조사 위치를 알 수 있는가. 저장·불러오기 안내가 실제 동작과 같은가. |

## 확인하고 수정한 불편

1. 단서함에서 자료를 눌러도 본문이 열리지 않고 선택만 됐다. 자료를 누르면 바로 읽고, 아래 ‘고르기’로 제시할 자료를 선택하도록 분리했다.
2. 세 번째 자료를 고르면 먼저 고른 자료가 말없이 빠졌다. 두 개를 유지하고, 하나를 해제한 뒤 고르라는 안내를 표시한다. 상세 화면에서 선택을 교체할 때는 버튼에 교체를 명시한다.
3. 마지막 대사를 읽은 뒤 버튼을 눌러도 화면만 이동했다. 일반 서술은 현장으로 돌아가고, 구조 중에는 구조 행동을 계속한다. 대화 중에는 질문 목록으로 이동하면서 첫 질문 버튼에 초점을 둔다.
4. 들었던 질문과 새 질문을 구분하기 어려웠다. 현재 진행 기록에 남은 질문에는 ‘들었던 답’을 붙였다. 게임이 반복 행동을 압축해 기록에서 제외한 경우까지 읽음 표시를 보장하지는 않는다.
5. 단서가 많아지면 문서를 하나씩 열어야 했다. 자료 수첩에서 제목과 본문을 검색한다. 아직 발견하지 않은 단서는 검색하지 않는다.
6. 구조 준비를 누가 마쳤는지 한눈에 알기 어려웠다. 현재 응답을 확인한 이후에만 클라라의 등불, 마라의 제한핀, 요나의 안전줄 준비를 표시한다.
7. 세 사람의 준비를 마쳐도 준비하라는 안내가 계속됐다. 준비 완료 뒤에는 제어대로, 통로 안에서는 귀환으로, 귀환 뒤에는 줄 회수로 안내가 바뀐다.
8. 도입만 읽다 중단하면 ‘시작하기’로 보여 처음부터 다시 읽어야 할 것 같았다. 조사 행동이 없어도 읽던 위치가 유효하면 ‘이어 하기’를 표시한다.
9. 돌아온 사람이 현재 상황을 확인하려면 먼저 게임에 들어가야 했다. 시작 화면에 읽던 도입 또는 머물던 장소, 지금 할 일, 조사 기록 열기를 제공한다.
10. 지난 대화와 종료 안내에 저장되지 않는다고 적혀 있었다. 같은 브라우저에서 읽던 대사와 최근 기록을 복원한다는 실제 동작에 맞췄다. 진행 파일을 다른 기기로 옮길 때는 대사 위치가 포함되지 않는다는 구분은 유지한다.
11. 다른 결말을 보려면 전체 조사를 다시 해야 했다. 확인 후 마지막 종료 선택 하나만 되돌릴 수 있다. 발견한 자료는 유지하고, 종료 뒤에 읽은 대화 목록은 비운다.
12. 기록을 지우기 전에 백업하려면 확인창을 닫고 설정으로 돌아가야 했다. 초기화·불러오기·마지막 선택 되돌리기 확인창에 파일 받기를 넣었다. 손상된 기록이면 빈 진행 파일 대신 읽지 못한 원본을 받을 수 있다.
13. 배경 표시가 늦을 때 실패로 단정하는 문구가 나왔다. 지연과 실패를 구분하고, ‘조사할 곳’으로 계속 조사할 수 있다고 안내한다.
14. ‘지원 요청’이 조사 종료라는 점이 버튼에서는 불분명했다. ‘지원 요청하고 이번 조사 마치기’로 바꾸고 기존 확인 절차를 유지했다.
15. 나가기 버튼이 ‘작품 목록’이라고 표시됐지만 실제로는 게임 소개로 이동했다. 이동 대상과 문구를 일치시켰다.

## 검사 범위

`npm run test:tide`의 48개 검사에는 세 번째 자료 선택, 읽기와 고르기의 독립 동작, 결말 직전 복원, 준비 단계별 안내, 대사 다음 버튼의 역할을 포함한다. 기존 저장 오류 9개 검사와 효과음 모의 검사도 유지한다.

사람이 플레이할 때 질문이 잘 눈에 들어오는지, 작은 화면에서 문서를 읽기 편한지, 효과음이 적절한 크기로 들리는지는 아직 확인하지 않았다. 요청에 따라 브라우저 조작 검사는 하지 않는다. 따라서 ‘모든 사용성 문제가 없어졌다’고 평가하지 않는다.

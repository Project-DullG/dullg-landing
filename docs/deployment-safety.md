# 운영 배포 전 검사

운영 배포에 사용할 커밋을 `main`에 반영하고 원격 저장소에 푸시한 뒤 실행한다.

```sh
node scripts/check-deploy-ready.mjs
```

다음 조건을 모두 만족할 때만 종료 코드 `0`을 반환한다.

- 현재 `HEAD`가 `origin` 서버의 `refs/heads/main`과 같다.
- 추적 중인 파일에 커밋하지 않은 변경이 없다. 스테이징한 변경도 검사한다.
- Git에 추가하지 않은 파일이 없다. Git의 무시 규칙에 해당하는 파일은 제외한다.

조건을 만족하지 못하거나 원격 저장소에 접근하지 못하면 종료 코드 `1`과 차단 이유를 출력한다. 검사를 생략하는 옵션은 없다. 배포 명령은 검사가 통과했을 때만 실행해야 한다.

## 원격 커밋 확인

`git ls-remote --exit-code origin refs/heads/main`으로 서버에 저장된 커밋을 조회한다. 로컬의 `origin/main`이 오래되었더라도 서버의 최신 커밋과 비교한다. 현재 커밋이 원격보다 뒤처진 경우뿐 아니라 앞선 경우와 이력이 갈라진 경우도 차단한다.

원격 커밋 객체가 로컬에 없으면 두 커밋의 선후 관계는 판정하지 않는다. 이 경우에도 커밋이 다르면 차단한다. 검사는 `fetch`, `pull`, `checkout`, `commit`, `push`, 배포 명령을 실행하지 않는다. Git 인덱스의 자동 갱신도 끈다.

## 적용 범위

- 이 검사는 실행 시점의 Git 상태를 확인한다. 실제 배포를 실행하지 않으며, 직접 실행한 배포 CLI를 가로막지는 않는다.
- 검사 후 파일이나 원격 `main`이 바뀌면 다시 검사해야 한다. 검사 통과가 이후 시점의 상태까지 보장하지는 않는다.
- 무시된 환경 설정 파일, 빌드 결과물, 배포 서비스 설정과 비밀 값은 검증하지 않는다. 무시 규칙에 들어 있는 파일을 배포하는 명령이라면 해당 파일을 별도로 검토해야 한다.
- 서비스 응답, 빌드 성공 여부, 배포된 버전은 별도로 확인해야 한다.

## 테스트

```sh
node --test tests/deploy-readiness.test.mjs
```

임시 디렉터리 안에 작업 저장소와 로컬 원격 저장소를 생성한다. 실제 프로젝트의 Git 상태와 외부 원격 저장소는 변경하지 않는다. 커밋 일치, 뒤처진 커밋, 푸시 전 커밋, 갈라진 이력, 오래된 `origin/main`, 미커밋 변경, 미추적 파일, 무시된 파일, 원격 접근 실패를 검사한다.

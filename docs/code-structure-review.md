# 코드 구조 점검

## 판단

콘텐츠가 코드에 저장되어 있다는 이유만으로 모두 잘못된 하드코딩은 아니다. 작품, 펀딩, 활동 기록은 이미 `lib`의 데이터와 화면 컴포넌트로 나뉘어 있다. 현재 규모에서는 CMS를 새로 도입하기보다 중복된 정보와 UI를 제거하는 편이 수정 범위가 작다.

## 이번에 수정한 부분

- 두 어드벤처 게임의 소개 카드 마크업을 `components/game-feature.tsx`로 합쳤다.
- 제목, 이미지, 소개문, 실행 주소는 `lib/featured-games.ts`에서 관리한다. 페이지 이동과 독립 HTML 실행을 구분해 영어 주소 접두어가 게임 파일에 붙지 않도록 했다.
- 퇴원일이 다른 게임 폴더의 CSS를 가져오던 의존성을 제거했다. 공통 스타일은 `components/game-feature.module.css`에서 관리한다.
- 기존 카드 컴포넌트는 호출부를 보존하는 작은 래퍼로 남겼다. 게임별 플레이 로직은 변경하지 않았다.
- 판매처와 작품별 상품 ID를 분리했다. 구매 버튼은 판매처 이름과 문구를 데이터에서 읽는다. 알 수 없는 작품 키는 구매 버튼을 표시하지 않는다.
- 퇴원일 카드의 영어 조건문을 기존 번역 방식으로 통일했다.
- 경로, 이미지, 상품 ID, 알 수 없는 키, 영어 실행 링크에 회귀 테스트를 추가했다.

## 다음 정리가 필요한 부분

- 문장 전체를 키로 사용하는 번역 사전은 문구 변경 때 이전 키가 남을 수 있다. 페이지 단위의 고정 키로 옮기려면 기존 번역 함수와 호출부를 함께 바꿔야 한다.
- 퇴원일의 입력 처리·오디오·저장·퍼즐 UI는 하나의 큰 파일에 있다. 저장 형식과 게임 분기 테스트를 유지하면서 기능별로 나눌 필요가 있다. 이번에는 게임 로직을 분리하지 않았다.
- 페이지 목록, 메뉴, 콘텐츠 사이의 경로 중복은 통합 후보지만, 현재 관련 파일에 별도 진행 중인 변경이 있어 이번 수정에서 제외했다.

## 추가 작업 방법

소개 카드와 같은 형식의 게임을 추가할 때는 게임 카탈로그와 번역을 등록한 뒤 공통 카드를 사용한다. 새 판매처는 판매처 목록에 등록하고 작품별 상품 ID를 연결한다. 새 UI를 별도 파일에 복사하지 않는다.
